# Q-020：`damageResults` 与 `DamageCap`

> 这份文档回答：Bob's Buddy 写出的 `damageResults` 有没有被该 Input 的 `DamageCap` 截断，符号怎么读，胜和平是不是 0。

```text
实测环境：本机 BgHelperDiag（%APPDATA%\HearthstoneDeckTracker\BgHelperDiag）
          43 局、487 场 Combat 且带 Output 的真实对战（HDT 自己跑的模拟，不是交叉重放）
          引用局：BB 1.85.0.0（HDT 1.58.6，插件 0.1.0）与 BB 1.88.6.0（HDT 1.58.9，插件 0.2.0）
工具：spikes/score-policy/q020_scan.py
最后核实：2026-10-11
```

上限何时写入 Input：仅当 `BACON_COMBAT_DAMAGE_CAP_ENABLED` > 0 时，HDT 把 `BACON_COMBAT_DAMAGE_CAP` 赋给 `Input.DamageCap`（`Hearthstone Deck Tracker/BobsBuddy/BobsBuddyInvoker.cs:913–914`，基线 `78cdc2a7`）。记录里的 `DamageCap=0` 与「上限关闭」同现；本文件不把 0 当成「伤害必须为 0」。

## 结论

**正的伤害上限会截断 `damageResults`。** `DamageCap` 为 5、10 或 15 的 445 场里，没有任何一条样本的绝对值大于该上限。上限为 0 的 42 场全部出现绝对值大于 15 的样本，所以模拟器在上限关闭时会写出超过 5/10/15 的数。

因此这批分布不能当作「未被上限截断的伤害」。后续对战得分的伤害系数取 0，不补伤害分位列。

## 五场对照

每场取该回合最后一条 `state=Combat` 且 `hasOutput` 的转储。`n` 是 `damageResults.items` 的条数。

| 局 | BB | 回合 | 上限 | 胜/平/负 | 样本 | 最小…最大 | 读法 |

| `20261010_215935_e8baef` | 1.88.6.0 | 1 | 5 | 0 / 1 / 0 | 19998 | 0…0 | 全平，全是 0 |
| `20261011_104243_194be4` | 1.88.6.0 | 1 | 5 | 0 / 0 / 1 | 19998 | −2…−2 | 全负，全是 −2，不到上限 |
| `20261010_215935_e8baef` | 1.88.6.0 | 4 | 10 | 0.325 / 0.440 / 0.235 | 19998 | −8…6 | 0 有 8790 条，8790/19998=0.440，与平率一致 |

| `20261004_220813_62725a` | 1.85.0.0 | 14 | 0 | 0.385 / … | — | −32…21 | 上限关闭时，样本可以大于 15 |

第三场说明 0 对得上平局，不是「没打过上限所以记 0」。第四场是「场面明显打得过当回合上限，结果却全部贴在上限上」。同口径下还有 23 场：胜率 ≥0.99、己方攻击合计 + 酒馆等级 > 上限 + 5，但约 2 万次结果全部等于 +上限（例如 `20261004_220813_62725a` 回合 13，上限 15，攻击合计 2871，结果全是 15）。

另有不到上限的全胜：`20261011_110743_5e3739` 回合 2，上限 5，结果全是 3。上限是天花板，不是把所有结果改成上限。

## 符号

- **正：** 己方造成伤害（全胜时样本全为正，或在平局份额之外为正）。
- **负：** 己方受到伤害（全负时样本全为负）。
- **0：** 与平率一致。全平时全部为 0。全胜时不为 0。

`avDamage` / `medianDamage` 与上述样本同号。HDT 把 `damageResults` 整表交给显示（`BobsBuddyInvoker.cs:336, 351`），本测量没有改这些数。
