# 文档总览与写作规范

## 文档分类

本项目把"知识"按性质分开存放，避免事实、决定、过程混在一起：

| 类别 | 位置 | 回答的问题 | 生命周期 |
| --- | --- | --- | --- |
| 状态 | `status.md` | 现在在哪？下一步做什么？ | 持续覆盖更新 |
| 路线 | `roadmap.md` | 整体分几步？每步怎样算完成？ | 阶段变化时更新 |
| 背景 | `context/` | 为什么做？做什么、不做什么？术语是什么意思？ | 很少变化 |
| 事实 | `facts/` | 外部系统（HDT、Bob's Buddy、游戏）实际是怎样的？ | 随外部版本更新复核 |
| 决定 | `decisions/` | 我们选了什么？为什么？放弃了什么？ | 只增不改，可被取代 |
| 架构 | `architecture/` | 系统现在整体长什么样？ | 与已接受的 ADR 保持一致 |
| 方案 | `design/` | 某个模块具体怎么实现、怎么验收？ | 实现前写，实现后标注状态 |
| 调研 | `research/` | 还有哪些不确定？风险在哪？调研结论是什么？ | 问题关闭后保留记录 |
| 过程 | `process/` | 按什么流程工作？每个环节 agent 该怎么做？ | 流程改进时更新 |
| 日志 | `worklog/` | 每次会话发生了什么？ | 只追加 |

## 编号约定

- 任务：`P<阶段>-T<序号>`，例如 `P1-T3`。定义在 `roadmap.md`。
- 决策：`ADR-<四位序号>`，文件名 `decisions/NNNN-short-title.md`。
- 未决问题：`Q-<三位序号>`，登记在 `research/open-questions.md`。
- 设计方案：`design/P<阶段>-<short-title>.md`。
- 工作日志：`worklog/YYYY-MM-DD-short-title.md`。

文档之间互相引用时用编号 + 相对链接，例如"见 [ADR-0002](decisions/0002-bobsbuddy-as-primary-simulator.md)"。

## 写作规范

- 用简体中文；代码、标识符、游戏标签名（如 `TAG_SCRIPT_DATA_NUM_1`）保持英文原样。
- 引用 HDT 源码写成 `Hearthstone Deck Tracker/BobsBuddy/BobsBuddyInvoker.cs:519`，并在文档头部注明基线 commit。
- 区分三种确定性：**已核实**（有代码或实测证据）、**推断**（有依据但未验证）、**未知**。不确定时宁可写"未知"。
- 每份文档开头写一句"这份文档回答什么问题"，读者能据此判断要不要读下去。
- 不写过程性流水账到事实/架构文档里；过程放 `worklog/`。
