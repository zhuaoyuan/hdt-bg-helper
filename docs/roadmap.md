## P1 战斗模拟器数据清单 ✅

**目标：** 得到一份"要让 Bob's Buddy 重现某一场战斗，必须采集哪些数据"的完整清单，每个字段注明来源、采集时机和可见性。

- [x] P1-T1 静态分析 HDT 中构造模拟器输入的全部代码：`BobsBuddyInvoker.cs`、`BobsBuddyUtils.cs`、`TagChangeActions.cs` / `PowerHandler.cs` 中所有调用 `BobsBuddyInvoker` 的位置
- [x] P1-T2 检查 `BobsBuddy.dll` 公开 API：能否在插件或独立进程中自行构造 `Input` 并调用 `SimulationRunner`（Q-001，结论见 `facts/bobsbuddy-public-api.md`）
- [x] P1-T3 对清单每个字段标注：采集时机（战斗前快照 / 战斗中揭示 / 派生计算）、可见性（己方 / 对手 / 队友）、是否版本敏感
- [x] P1-T4 确认 HDT 日志中 Bob's Buddy 输入/输出的记录完整度，评估能否作为对照基准（Q-004，结论见 `facts/hdt-log-simulation-input.md`）
- [x] P1-T5 发布数据清单 v1，并列出已知覆盖缺口（所有者 2026-09-26 接受带缺口的 v1；缺口转入 P2-T6 长期监控）

**退出标准：**
1. 清单覆盖 `SetupInputPlayer`、`SnapshotBoardState` 及全部战斗中更新入口写入的每一个 `Input` 字段；
2. Q-001 有明确结论（可直接调用 / 需反射 / 不可行）；
3. 所有者审阅通过。

## P2 个人局内数据收集工具

**目标：** 一个 HDT 插件，在每场酒馆战棋对局中可靠地保存"模拟就绪"的战斗快照，并能证明保存下来的数据是对的。

- [ ] P2-T0 **离线重放工具**：把诊断记录里 HDT `_input` 的反射转储按字段还原成 BB `Input`，在独立进程里模拟，与记录的 `Output` 对照。同时用于 Q-009（耗时）、Q-011（跨 BB 版本）、Q-013（未赋值字段）实验，是 P2-T5 和 P3-T0 的前置
- [ ] P2-T1 设计方案：采集时机、原始/标准/模拟三层数据模型、存储格式、schema 版本策略（`design/P2-data-capture.md`）。须包括：诊断插件记录可导入正式原始层（或正式格式是其超集）；压缩与保留策略（诊断原始记录约 10–19 MB/局）；以 HDT `_input` 反射转储为主数据源、实体快照为后备的取舍（写 ADR）
- [ ] P2-T2 插件工程骨架：`IPlugin` 实现、构建、部署到 HDT 插件目录、日志
- [ ] P2-T3 原始层采集：战斗开始时的实体/标签快照 + 战斗中揭示信息 + 战斗结果
- [ ] P2-T4 标准层投影与完整性判定（`ready` / `partial` / `unsupported` / `invalid`）
- [ ] P2-T5 **往返验证**：由采集数据重建 `Input` → 运行 Bob's Buddy → 与 HDT 当场显示的胜率对照
- [ ] P2-T6 数据质量报告：每局采集成功率、各完整性状态占比、往返验证偏差；持续跟踪 P1 清单 v1 的覆盖缺口（双人、畸变、Malorne、任务、战斗中补录、`2717` 等）何时出现正例；HDT 升级后的冒烟检查
- [ ] P2-T7 **赛后复盘报告 v0**：每回合 HDT 当场胜率、实际战斗结果、掉血、最终名次。先给所有者可用的产出，也作为以后检验"战力分位是否比 HDT 胜率多提供信息"的基线

**退出标准（占位，P2-T1 修正）：** 连续 10 局真实对局中，`ready` 快照占比 ≥ 90%，且 `ready` 快照往返验证的胜/平/负率与 HDT 当场结果之差在蒙特卡洛误差范围内（1 万次模拟约 ±1 个百分点）。

## P3 战力评估引擎（离线）

**目标：** 对任意 `ready` 快照，给出"本回合战力分位"及其置信度（定义见 [ADR-0003](decisions/0003-strength-metric-definition.md)）。

- [ ] P3-T0 **核心假设早期验证**（依赖 P2-T0，可与 P2 并行）：用已有诊断记录（双方场面）做全交叉模拟，算 S(x) 与分位，评估单局计算成本、分位随参照池大小的稳定性（bootstrap）、与实际战斗结果/承伤的相关性、相对 HDT 当场胜率有无增量信息；对照替代指标"对固定基准场面集的平均胜率"。结论约束 P2 采集范围和 P3-T1 放宽规则，必要时触发 ADR-0003 的推翻条件
- [ ] P3-T1 设计方案：参照池选择与放宽规则、抽样与加权、缓存、置信区间
- [ ] P3-T2 批量模拟服务（状态哈希去重、结果缓存、模拟器版本标记）
- [ ] P3-T3 分位计算与不确定度输出
- [ ] P3-T4 指标有效性评估（区分度、稳定性、与后续承伤的关系）
- [ ] P3-T5 复盘视图原型（按回合展示分位、置信度、实际对手和结果）

**退出标准（占位，P3-T1 修正）：** 回合 ≤ 12 的 `ready` 快照，分位的 bootstrap 95% 区间宽度 ≤ 20 个百分位点；P3-T4 显示分位与后续战斗结果的相关性显著，且相对 HDT 当场胜率有增量信息；单局全部回合的后台计算在 Q-009 的耗时标准内完成。
