## P1 战斗模拟器数据清单

**目标：** 得到一份"要让 Bob's Buddy 重现某一场战斗，必须采集哪些数据"的完整清单，每个字段注明来源、采集时机和可见性。

- [ ] P1-T1 静态分析 HDT 中构造模拟器输入的全部代码：`BobsBuddyInvoker.cs`、`BobsBuddyUtils.cs`、`TagChangeActions.cs` / `PowerHandler.cs` 中所有调用 `BobsBuddyInvoker` 的位置
- [ ] P1-T2 检查 `BobsBuddy.dll` 公开 API：能否在插件或独立进程中自行构造 `Input` 并调用 `SimulationRunner`（Q-001）
- [ ] P1-T3 对清单每个字段标注：采集时机（战斗前快照 / 战斗中揭示 / 派生计算）、可见性（己方 / 对手 / 队友）、是否版本敏感
- [ ] P1-T4 确认 HDT 日志中 Bob's Buddy 输入/输出的记录完整度，评估能否作为对照基准（Q-004）
- [ ] P1-T5 发布数据清单 v1，并列出已知覆盖缺口

**退出标准：**
1. 清单覆盖 `SetupInputPlayer`、`SnapshotBoardState` 及全部战斗中更新入口写入的每一个 `Input` 字段；
2. Q-001 有明确结论（可直接调用 / 需反射 / 不可行）；
3. 所有者审阅通过。

## P2 个人局内数据收集工具

**目标：** 一个 HDT 插件，在每场酒馆战棋对局中可靠地保存"模拟就绪"的战斗快照，并能证明保存下来的数据是对的。

- [ ] P2-T1 设计方案：采集时机、原始/标准/模拟三层数据模型、存储格式、schema 版本策略（`design/P2-data-capture.md`）
- [ ] P2-T2 插件工程骨架：`IPlugin` 实现、构建、部署到 HDT 插件目录、日志
- [ ] P2-T3 原始层采集：战斗开始时的实体/标签快照 + 战斗中揭示信息 + 战斗结果
- [ ] P2-T4 标准层投影与完整性判定（`ready` / `partial` / `unsupported` / `invalid`）
- [ ] P2-T5 **往返验证**：由采集数据重建 `Input` → 运行 Bob's Buddy → 与 HDT 当场显示的胜率对照
- [ ] P2-T6 数据质量报告：每局采集成功率、各完整性状态占比、往返验证偏差

**退出标准：** 连续 N 局（N 由设计方案确定）真实对局中，`ready` 快照往返验证结果与 HDT 当场结果在蒙特卡洛误差范围内一致。

## P3 战力评估引擎（离线）

**目标：** 对任意 `ready` 快照，给出"本回合战力分位"及其置信度（定义见 [ADR-0003](decisions/0003-strength-metric-definition.md)）。

- [ ] P3-T1 设计方案：参照池选择与放宽规则、抽样与加权、缓存、置信区间
- [ ] P3-T2 批量模拟服务（状态哈希去重、结果缓存、模拟器版本标记）
- [ ] P3-T3 分位计算与不确定度输出
- [ ] P3-T4 指标有效性评估（区分度、稳定性、与后续承伤的关系）
- [ ] P3-T5 复盘视图原型（按回合展示分位、置信度、实际对手和结果）

**退出标准：** 待 P3-T1 定义。

## P4 HDT 实时集成

**目标：** 对局中在 HDT 覆盖层低干扰地显示当前战力分位与置信度，不影响 HDT 与游戏性能。

- [ ] P4-T1 设计方案：计算时机与延迟预算、缓存/预计算策略、覆盖层 UI
- [ ] P4-T2 实现与性能验证
