# 愿景、目标与边界

> 这份文档回答：为什么做这个项目，要达到什么，不做什么。来源是所有者与 AI 的早期讨论（[`early_discussion.md`](early_discussion.md)），修改需所有者确认。

## 最终目标

**提升所有者本人的酒馆战棋水平。** 这是一个"对局 → 数据 → 分析 → 复盘 → 再对局"的人机协同问题，不是训练一个能打游戏的 AI。

## 核心思路（已确认）

1. 把复杂的局面压缩到少数可解释的维度。底层只保留一个维度：**战力**。方向选择的合理性是"战力 + 回合 + 血量 + 当前牌"的次级问题。
2. 战力不靠手工公式打分，而是定义为**本回合战力分位**：把当前战斗前场面与大量同条件历史场面放进战斗模拟器对战，看它的表现超过多少比例的参照场面。
3. 这种定义天然跟随版本：只要采集的数据完整、模拟器支持当前版本，版本变化会自动反映到参照池和模拟结果里，不需要重写评分规则。
4. 因此**数据采集**和**战力评估引擎**是整个系统最重要的两块。

## 分阶段目标

见 [`../roadmap.md`](../roadmap.md)：数据清单 → 采集工具 → 战力评估引擎 → HDT 实时集成 →（远期）方向决策。

## 设计原则

- **采集以模拟器输入为准**，不以画面上看得到什么为准。没看到的信息记为"未知"，不能默认为不存在。
- **原始数据尽量全留**。字段含义可能随版本变化，保留原始实体和标签，以后可以重新解析。
- **可追溯、可复算**。每个评分结果都记录卡牌数据版本、规则上下文和模拟器版本。
- **不确定就明说**。样本不足、模拟误差大时，显示"不稳定"，而不是给一个看起来精确的数。
- **局内低干扰**。游戏中只显示少量高价值信息，重分析放到赛后。
- **适配版本靠替换模块**。大版本更新时，期望只需调整少数模块（卡牌数据、模拟器、规则指纹），不推倒重来。

## 不做（范围红线）

- 自动操作游戏、宏、代打。
- 爬取 HSReplay 会员页面。HSReplay 数据只用人工导入或合规导出。
- 公开或上传其他玩家的身份信息。本地存储时匿名化，不需要跨局识别对手时不保存 BattleTag。

## 已知的主要风险

详细登记在 [`../research/open-questions.md`](../research/open-questions.md)，最关键的两个：

1. 战斗状态能否被**完整**采集（很多影响战斗的信息藏在附魔、玩家级计数器、战斗中才揭示的手牌/奥秘里）。
2. Bob's Buddy 能否在 HDT 自身流程之外被**稳定地、对任意两个场面**调用。
