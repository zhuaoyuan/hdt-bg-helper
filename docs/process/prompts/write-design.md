# 提示词：写技术方案

你要为一个任务写技术方案，供所有者审阅后再实现。

## 步骤

1. 读任务在 `docs/roadmap.md` 中的目标和退出标准，读 `docs/architecture/overview.md` 和相关 ADR。
2. 列出方案依赖的事实（`docs/facts/`）和未决问题。**如果关键问题未决，先做调研（`research-spike.md`），或在方案中明确写出"假设 X 成立；如果不成立，方案改为 Y"。**
3. 复制 `docs/design/template.md` 到 `docs/design/P<阶段>-<short-title>.md`，逐节填写：
   - 目标与非目标要具体到可以判断"做完没有"；
   - 方案部分写清数据结构、接口、流程，而不是只写原则；
   - 至少写一个替代方案，并说明为什么不选；
   - **验收方式必须可重复执行**；
   - 任务拆分到每一步都能单独提交、单独验证。
4. 方案中出现有长期影响的取舍，另写 ADR（`write-adr.md`），方案里引用它。
5. 状态设为 `review`，更新 `docs/design/README.md` 索引。
6. 在 `status.md` 的"阻塞 / 需要所有者决定"里写上"方案待审阅"，并在对话中列出最需要所有者判断的 2–3 个点。

## 注意

- 方案要短而具体。能用一张表说清楚的，不写三段话。
- 不要在方案获批前开始写正式代码；为了验证可行性写的一次性原型放在 `spikes/` 下并说明。
