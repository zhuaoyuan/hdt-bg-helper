# 提示词：调研（Research Spike）

你在执行一个调研任务。目标是把"不确定"变成"有证据的事实"或"明确的未知"，而不是写代码。

## 输入

- 任务编号（如 `P1-T1`）或问题编号（如 `Q-001`）。
- 相关文档：`docs/roadmap.md` 中该任务的描述，`docs/research/open-questions.md` 中相关问题，`docs/facts/` 中已有内容。

## 步骤

1. **定义问题。** 用一两句话写下这次要回答什么、答到什么程度算完成。如果任务描述不够具体，先在 worklog 写下你的理解。
2. **先查已有事实。** 读 `docs/facts/` 相关文档，不重复调研已核实的内容；如果发现已有事实可能过时（基线不同），先标出来。
3. **找一手证据。** 优先级：HDT 源码（基线版本）> 实测 > 官方文档 > 第三方插件源码 > 其他资料。引用源码写到文件和行号。
4. **区分确定性。** 每条结论标明是"已核实"还是"[推断]"。推断要写清楚依据和验证方法。
5. **不越界。** 调研中发现的设计想法，记到 worklog 或未决问题里，不要顺手写成决定或代码。
6. **写回仓库：**
   - 事实 → `docs/facts/` 对应文档（更新"最后核实"日期）；
   - 新问题 → `open-questions.md` 新增条目；
   - 已回答的问题 → 移到"已关闭"，写明结论和结论所在位置；
   - 出现需要取舍的地方 → 按 `write-adr.md` 起草 `proposed` ADR；
   - 过程与发现 → `docs/worklog/`。
7. **收尾**：按 `session-handoff.md` 执行。

## 产出检查

- [ ] 每条新事实都有来源和基线版本
- [ ] 没有把推断写成事实
- [ ] 相关未决问题的状态已更新
- [ ] 如果任务没做完，`status.md` 写清楚做到哪、下一步从哪继续
