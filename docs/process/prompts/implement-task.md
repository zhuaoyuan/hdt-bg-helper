# 提示词：实现任务

你要按已批准的方案（或一个不需要方案的小改动）实现代码。

## 开始前

1. 确认方案状态是 `approved`（小改动除外）。如果不是，停下来说明原因。
2. 读方案的"任务拆分"，选当前这一步；读相关的事实文档和 ADR。
3. 从 `main` 新建分支：`feat/P2-T3-short-desc` 这样的格式。

## 实现

- 一次只做方案里的一步，完成后再做下一步。
- 与 HDT 相关的逻辑（例如从实体构造 Bob's Buddy 输入），在代码注释里写明对应的 HDT 源码位置和基线版本，方便升级时对照。这是少数值得写的注释之一。
- 遇到方案没覆盖的情况：
  - 小问题：按最保守的方式处理，在 worklog 里记录；
  - 会改变方案的问题：停下来，更新方案或提 ADR，不要自行扩大范围。
- 采集相关代码：宁可把信息记为"未知"，也不要给默认值；绝不能因为采集失败抛异常影响 HDT。

## 测试与验证

- 为每个改动写测试；无法自动测试的（需要真实对局），写清楚人工验证步骤，交给所有者执行。
- 涉及采集或模拟的改动，按 `verify-data.md` 做验证。

## 提交

- 每个可独立验证的改动一个 commit，消息用约定式前缀（`feat:`、`fix:`、`test:`……），正文简述为什么。
- 提交前按 `review.md` 自审。
- 不要 push，除非所有者要求。

## 收尾

- 方案中对应步骤标注完成；与方案有偏差的写到方案的"实现记录"里。
- 按 `session-handoff.md` 更新状态和日志。
