# 提示词：数据质量与往返验证

你要证明采集下来的数据是对的、足以驱动模拟。"代码跑通"不等于"数据正确"。

## 三层检查

### 1. 结构完整性（自动）

- 每局、每回合都有快照吗？同一玩家同一回合有没有互相冲突的重复快照？
- 各完整性状态（`ready` / `partial` / `unsupported` / `invalid`）占比多少？`partial` 和 `unsupported` 的主要原因是什么？
- 有没有字段被填了默认值而不是标记为未知？

### 2. 往返验证（自动 + 真实对局数据）

1. 用采集数据重建 Bob's Buddy 输入，运行模拟。
2. 与 HDT 当场的 Bob's Buddy 结果对照（来源可以是 HDT 日志中的 Output 段落，或通过反射取得的 HDT 结果，取决于 Q-002 / Q-004 的结论）。
3. 判定标准：胜 / 平 / 负概率之差在蒙特卡洛误差范围内（10,000 次模拟时，单个概率的标准误约为 \( \sqrt{p(1-p)/10000} \le 0.5\% \)，差值超过约 2 个百分点就要查原因）。
4. 对不一致的样本逐个排查：是采集缺字段、转换逻辑错误，还是战斗中揭示的信息没合并。

### 3. 人工核对（需要所有者）

- 从最近的对局里挑几个回合，让所有者对照游戏画面或回放核对：随从、属性、顺序、金色、关键词、饰品、任务、英雄技能状态。
- 提供一份核对清单，所有者只需要勾选或指出不符。

## 产出

- 一份质量报告（放在 `docs/worklog/` 当天记录里，或 `tools/` 生成的报告路径），包括：样本数、各状态占比、往返验证通过率、主要问题及原因。
- 发现的采集缺口登记到 `open-questions.md` 或直接更新数据清单。
- **注意：** 不要用"模拟胜率是否等于单场实际输赢"来判断对错，单场战斗有随机性。实际战斗结果只能用于大量样本的统计校准。
