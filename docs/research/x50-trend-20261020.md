# 现版本 X50 时序：我 vs 对手，分回合战力有没有随时间漂移

- **日期：** 2026-10-20
- **状态：** 探索性描述分析（spike；不改 `strength.jsonl`、不改分位参照池、不做因果解释）。方案：`docs/design/R-x50-trend.md`。
- **数据：** 现版本 = Bob's Buddy DLL **1.88.6.0** 的 **81 局**（2026-10-07～10-17）；己方 \(X_{50}\) 来自 `spikes/dummy-ladder/out-adaptive-all/curves.json`，对手 \(X_{50}\) 为本次新测 `spikes/dummy-ladder/out-opp-188/curves.json`（937 板，`DummySim --measureSide opponent`）；版本/回合来自 `data/standard/turns.jsonl`。**扩展复核**（§10）把池内前一兼容版本 **1.85.0.0**（31 局，2026-10-02～10-06）并入，得到 112 局 / 16 天、两侧各 814/812 个 t5–12 interior 板。
- **工具：** `spikes/x50-trend/{build_dataset,analyze,verify}.py`、`spikes/dummy-ladder/{run_adaptive,verify_side_opp}.py`；输出在 `spikes/x50-trend/out/`（gitignore）。
- **口径：** 只用 `status=interior`；主窗口 t5–12（\(X_{50}\) 在 t5 以前不稳、t13 以后样本 <35）；时间轴 = `gameId` 升序（`YYYYMMDD_HHMMSS`）；10 局 trailing 均线在 \(\log_2\) 域，满窗口才画。

## 0. 结论（先看这个）

1. **没有可检测的时间漂移。** 81 局、10 天窗口，主检验（\(\log_2 X_{50} \sim\) 对局顺序 + 回合固定效应，按局聚类 bootstrap）：
   - **我：−0.6%/10 局**，95% CI **[−3.0, +1.7]**，p=0.59；
   - **对手：+0.5%/10 局**，95% CI **[−2.3, +3.4]**，p=0.76；
   - **对局强度（两侧几何均值）：−0.1%/10 局**，95% CI **[−2.3, +2.0]**，p=0.94；
   - 相对难度（\(\log_2\) 我/对手）：−1.2%/10 局，CI [−4.2, +1.8]，p=0.43。
   - 四个检验 BH **q=0.94**。分回合 16 个检验也无一显著（最小未校正 p=0.089：t8 我 −2.7%/10 局，BH q=0.71）。
2. **能排除多大的漂移？** 按 81 局累计：我 [−22%, +15%]、对手 [−17%, +30%]、强度 [−17%, +17%]（95% CI）。即"11 天内对局强度持续变强/变弱超过约 ±17%"可以排除；每 10 局的 80% 功效 MDE 为 **3.1–4.2%**，所以"每 10 局 ±5%"这种量级的短期波动当前分辨不了。
3. **两侧曲线形状一致。** t5→t12 中位 \(X_{50}\) 从约 **4.9 / 4.5** 升到 **502 / 622**（我/对手），约每回合 ×1.9–2.0（t5–t12 累计约 ×100；图 3）；这是回合维度（战斗强度随回合指数增长），不是时间维度。时间维度上两条均线都基本水平（图 1、图 2）。
4. **相对难度也没有随时间变。** 中位 \(\log_2\)(我/对手) 在 t5–9 为 +0.07～+0.29，t10–12 转为 −0.03～−0.47；这是**晚回合存活选择**（能活到 t11–12 的对手只剩强者），其时间趋势本身不显著，不能解读为"对手越来越强"。
5. **稳健性一致。** 前后半段、去掉 t5、剔除 CI 缺失/过宽板（各侧约 27%/31%）、局级回合调整指数趋势、按天 Kendall τ，点估计都在 ±1%/10 局内、CI 全跨 0；存活回合没有随时间变化（ρ=0.076，p=0.50），回合组成不构成伪趋势。
6. **与 2026-10-11 的分位版结论一致**（当时 56 局、相对分位：ρ≈0.01/0.10/0.11）。这次用绝对刻度、两侧同板、81 局，结论仍是"这个窗口内看不出对局强度随时间变化"。**主池 `(simPool, turn)` 暂不需要按时间校准**；长期（跨月/跨 patch）是否漂移仍需复看。
7. **对手侧 \(X_{50}\) 是本次新增口径，已做换侧 ground truth 校验**：把同一块板搬到对手侧、`ControlledByPlayer` 按真实对手置 false 后，与己方侧测量一致（中位差 0.16%、最大 0.97%、CI 重叠 5/5、status 6/6）。因此"我和对手"两条线可以直接比较（细节 §3.4）。
8. **加入前一兼容版本（1.85.0.0）复核后结论不变、且更紧（§10）**：112 局 / 16 天，我 **+0.1%/10 局** [−1.3, +1.5]、对手 **+0.2%** [−1.1, +1.7]、强度 **+0.2%** [−0.9, +1.2]，BH q=0.91；累计漂移 CI 收窄到约 ±14–20%（MDE 1.6–2.3%/10 局）。**没有检测到版本切换台阶**：1.88.6 vs 1.85 的层差 我 +7.5% [−25, +56]、对手 −13.0% [−39, +22]、强度 −5.0% [−28, +23]，版本×时间斜率差也全跨 0；但 1.85 只有 31 局、且版本边界与日历时间共线，不能排除 ±25–40% 的版本/时段层差。

## 1. 为什么问这个

分位引擎的参照池是 `(simPool, turn)`，隐含假设"同一回合的强度分布在这个池内平稳"。如果对局强度随日历时间单调上升（MMR 爬升、玩家群变强、meta 变快），历史参照会系统性偏低、当前局面被高估（或反之）。上一轮 `R-progress-trend` 用**相对分位**看过 56 局，看不到趋势；分位是相对量，参照池本身在扩张，不能完全回答"绝对强度有没有变"。这次用木桩梯队的绝对刻度，且**自己和对手都测**。

## 3. 方法

### 3.1 \(X_{50}\) 测量

木桩梯队 v2：真实场面一侧 + 7 个同攻血（攻=血=L）无词条木桩；自适应粗档 ratio4 + 2 轮 4+2 点加密，iterations=500；logistic 位置估计给出 \(X_{50}\) 与 95% CI。己方沿用 `out-adaptive-all`（该文件覆盖 112 局，本次只取其中 81 局 1.88.6.0；1.85 的 31 局不算现版本）。对手为本次新测（§3.4）。

### 3.2 10 点均线

要求"用 10 个点的均线平滑展示"。实现为 **10 局 trailing 均线**，在 \(\log_2 X_{50}\) 域计算（避免大回合主导），只对 `interior` 板滑动；**满 10 个有效板才画均线**，前 9 个位置只有原始点（否则前几个点会让曲线假性抬头/下探）。原始板点同时浅色显示。

### 3.3 主检验

\[
\log_2 X_{50,i} = \beta\,(\text{seq}_i-\overline{\text{seq}}) + \gamma_{t_i} + \varepsilon_i
\]

回合 5–12 固定效应（吸收"回合越晚越强"这一约 87% 的方差），**按局聚类 bootstrap**（整局重采样，B=2000）给斜率 CI；报告每 10 局变化百分比 \(2^{10\hat\beta}-1\) 与 81 局累计漂移 \(2^{80\hat\beta}-1\)。分别跑：我、对手、对局强度 \(I=\sqrt{X^{\text{me}}_{50}X^{\text{opp}}_{50}}\)（对数域即两侧 log 均值）、相对难度 \(\log_2(X^{\text{me}}_{50}/X^{\text{opp}}_{50})\)。四者 BH-FDR；分回合 8×2 检验单独 BH（探索性）。80% 功效 MDE 由 bootstrap 斜率 SD 反推。

### 3.4 对手侧测量与校验（新增）

`DummySim --measureSide opponent`：把 7 个木桩放到 `Input.Player` 侧、保留真实对手场面；模型估计量对调 win/loss（木桩恒在 Player 侧，输出是木桩视角）后再按 v2 拟合真实板视角。校验脚本 `spikes/dummy-ladder/verify_side_opp.py`：

| 校验 | 结果 |
| --- | --- |
| **A. 己方回归**：6 块 t6 板在固定梯子上重测 vs `out-adaptive-all` v2 | 中位 \|\(\log_2\) ratio\| **0.57%**（最大 7.83%，该板 GT CI 本身退化）；status 6/6 一致；CI 重叠 5/5 |
| **B. 换侧 ground truth**：同一块板搬到对手侧，`ControlledByPlayer` 递归置 false 后测 | 与己方侧口径 **中位 0.16%、最大 0.97%**；6/6 在 5% 内；CI 重叠 5/5；status 6/6 → **\(X_{50}\) 与板所在侧无关** |
| B'（反例）：保留 `ControlledByPlayer=true` 搬到对手侧 | 全废（木桩 1/1 都 99.5% 胜，\(X_{50}\) 0.19–0.98）→ 侧标志必须与所在侧一致；真实对手 dump 本来就是 false，主流程不受影响 |
| **C. 量纲**：opp/own 分回合中位 \(X_{50}\) 比 | 0.82–1.24（t13 1.46、t16 1.60、t17 1.85 但 n≤2）；Spearman(\(\log_2 X_{50}\), 板面 sum(atk+hp)) = **0.980**（己方 0.969）、vs 随从数 0.752（己方 0.801） |

对手 run：937 板，interior 799 / below 136 / above 2；墙钟 217.6 s；**errors 0、hydration warnings 0**；中位 CI 宽 0.148 log2。默认 player 路径回归：同一 Input 的 L1/4/16/64 与 `out-adaptive-all/round0.jsonl` 逐位一致。

### 3.5 稳健性与功效

(a) 前后半段（前 40 局 vs 后 41 局）中位对比；(b) 去掉最不稳定的 t5（t6–12）；(c) **trim**：剔除 CI 缺失或 \(\log_2\) 宽度 >1.0 的板（近阶跃拟合会给出退化 CI）；(d) **局级回合调整指数**：每块板减去同回合中位数后按局平均，再对 seq 回归（81 个点）；(e) 按天中位数的 Kendall τ（10 个点）；(f) 存活/回合组成漂移检查；(g) 早/晚残差分位数（不只均值）。

## 7. 限制

- **样本/窗口**：81 局、10 天、单一 BB 版本；只覆盖自己的匹配池。无法排除 ±3–4%/10 局级别的缓慢漂移；跨 patch/跨月必须重测。
- **选择效应**：晚回合只有幸存局进入样本（t12 只有 45 局），且晚回合对手是幸存强者；所以 t10–12 的"对手中位更高"不可解释为对局变强。
- **测量噪声**：\(X_{50}\) 单板中位 CI 宽约 0.13–0.15 log2（×1.09–1.11），会给斜率带来经典测量误差（轻微向 0 收缩），不改变"没有显著漂移"的结论；CI 缺失/近阶跃板已做 trim 稳健性。
- **不可观测混杂**：MMR、英雄选择、匹配池、当天的疲劳/时段都不在数据里；本报告只描述相关，不做因果。
- **对手侧口径**：本次新增，已用换侧 ground-truth 校验（§3.4），但仍依赖"真实对手 dump 的 `ControlledByPlayer=false`"这一前提；若未来采集版本改变该语义，需要重新校验。
- **"现版本"** 用 BB DLL 版本而非 Hearthstone patch（数据里没有可靠的 patch 字段）。

## 8. 与既有结论的关系

- 2026-10-11 的 `R-progress-trend`（相对分位、56 局、含 1.85/1.88.6 并池）结论是"看不出稳定上升"（ρ≈0.01/0.10/0.11）。本次改为**绝对刻度 + 两侧同板 + 只看现版本 81 局**，结论一致，且给出了可量化的排除范围（累计 ±17%）。
- 对 P3 的含义：**当前不需要按时间校准分位参照池**；X50/分位的 `(simPool, turn)` 口径在这个窗口内仍然可用。若要做长期监控，这套脚本（`build_dataset.py` → `analyze.py`）可以按版本重跑。
- 未改 `strength.jsonl`、未改主分位、未新增正式依赖；对手侧测量工具留在 `spikes/dummy-ladder/`。

## 9. 复跑与独立复核

```powershell
# 1) 对手侧 X50（约 4 分钟；已产出 out-opp-188，可跳过）
python spikes\dummy-ladder\run_adaptive.py --pool 1.88.6.0 --turns 1-17 --side opponent --out spikes\dummy-ladder\out-opp-188
python spikes\dummy-ladder\verify_side_opp.py        # 换侧 ground-truth 校验

# 2) 数据表 + 分析 + 图
python spikes\x50-trend\build_dataset.py
python spikes\x50-trend\analyze.py                    # 出 analysis.json + figs/*.png

# 3) 独立复算（不同数值路径 + 不同 bootstrap 种子）
python spikes\x50-trend\verify.py
```

- `verify.py`：用**去回合均值后的 OLS（Frisch-Waugh）**重算斜率、换 bootstrap 种子（20261020）重算 CI/p，并抽查分回合 ρ 与 t8 MA10。结果：点估计与 `analysis.json` **完全一致**（−0.629% / +0.464%），CI 端点差 ≤0.1pp（蒙特卡洛），ρ 与 MA10 精确一致。

### 10.3 方法

与 §3.3 相同的回合固定效应 + 按局聚类 bootstrap（B=2000）。另加：

\[
\log_2 X_{50,i} = \beta\,\text{seq}_i + \delta\,\text{ver}_i + \eta\,(\text{seq}_i\cdot\text{ver}_i) + \gamma_{t_i} + \varepsilon_i
\]

`ver=1` 表示 1.88.6（基准=1.85.0.0）。\(\delta\) = 版本切换台阶（层差），\(\eta\) = 版本内斜率差（趋势断裂）。注意：**版本虚拟变量与日历时间共线**（1.85 局全在更早的 6 天），所以 \(\delta\) 同时是"兼容版本效应"和"早期时段效应"；本分析只能回答"混入前一版本后有没有台阶"，不能把 \(\delta\) 因果归给 DLL。另做**版本内趋势**（只用 81 局 / 只用 31 局）。

### 10.5 结论

- **并入前一兼容版本后，"没有可检测的时间漂移"不变且更紧**：112 局 / 16 天，三条主线的点估计都在 ±0.25%/10 局内、CI 收窄约 40–50%，累计漂移的 95% CI 约 ±14–20%；80% 功效 MDE 1.6–2.3%/10 局。
- **没有检测到版本切换台阶或趋势断裂**（版本层差 p=0.39–0.70、BH q=0.70；版本×时间交互全跨 0）；但这一步受"1.85 只有 31 局 + 版本/时间共线"限制，只能作为"混版本不引入可见台阶"的检查，不能当作 DLL 兼容性的强证据（那由 Q-011 / 跨 DLL 重放负责）。
- 主池 `(simPool, turn)` 继续**不需要按时间校准**；若未来继续积累，可把 `spikes/x50-trend/` 作为换版本/每月的例行复看（改 `--pool` 即可同时纳入新版本）。
