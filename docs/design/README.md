# 技术方案

> 这份文档回答：什么时候要写技术方案，怎么写。

## 什么时候写

动手实现之前，只要满足任一条件就写一份方案（可以很短）：

- 改动涉及多个文件或多个组件；
- 引入新的数据格式、存储结构或外部依赖；
- 需要所有者验收的里程碑任务。

单文件的小修复不需要方案。

## 流程

1. 复制 [`template.md`](template.md)，命名为 `P<阶段>-<short-title>.md`。
2. 状态写 `draft`，完成后改为 `review`，请所有者审阅。
3. 审阅通过改为 `approved`，再开始实现；方案里产生的重要取舍另写 ADR。
4. 实现完成后改为 `implemented`，并注明与方案的偏差。
