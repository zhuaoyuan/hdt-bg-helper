# 方案：现版本「我 vs 对手」分回合 X50 时序

- **状态：** implemented（2026-10-20；spike 工具 `spikes/x50-trend/`，结论见 `docs/research/x50-trend-20261020.md`）
- **任务：** 主线外（探索）。用木桩梯队 v2 的 \(X_{50}\) 绝对刻度，看**现版本**（BB `1.88.6.0`）自己与对手的场面战力按回合是否随时间漂移；用 10 局滑动均线平滑展示。
- **作者 / 日期：** agent / 2026-10-20
- **相关：** `docs/facts/dummy-ladder-v2-20261019.md`（\(X_{50}\) 定义与可用范围）、`docs/design/R-progress-trend.md`（上一版分位时序）、ADR-0015（模拟池 `1.85.0.0`）

## 1. 目标与非目标

**目标：** 一条命令生成离线 HTML/PNG + 一份可复算的 CSV：

| 图 | 横轴 | 纵轴 | 线 |
| --- | --- | --- | --- |
| 各回合时序（小多图 t5–t12） | 对局顺序号（按 `gameId` 时间升序，1..N） | \(\log_2 X_{50}\) | 我 / 对手；细线=原始板，粗线=10 局 trailing 均线 |
| 汇总强度时序 | 对局顺序号 | 每局 \(\log_2 X_{50}\) 均值（我、对手、对局强度） | 原始 + 10 局均线 + 趋势线 |
| 回合剖面 | 回合 t | \(X_{50}\) 中位数（IQR） | 我 / 对手 |

**主问题：** 在这个 11 天窗口里，同回合的 \(X_{50}\) 有没有随时间单调趋势（"对局强度变强/变弱"）？
**对局强度** 定义为同一场战斗两侧的几何均值：\(I=\sqrt{X_{50}^{\text{me}}\,X_{50}^{\text{opp}}}\)（对数域即两侧 log 的算术平均）；同时单独报告两侧，避免把"我更弱"和"对局更弱"混为一谈。

**非目标：** 不改 `strength.jsonl`、不动分位参照池、不把结论外推到别的版本/玩家池、不做因果解释（MMR 爬升、英雄、匹配池变化都不在数据里）。

## 2. 口径与依据

- **现版本** = Bob's Buddy DLL `1.88.6.0`（本机 `C:\Program Files\HDT` 当前版本）的 **81 局**，2026-10-07～2026-10-17。跨 DLL 稳定性已由 v2 验证（Spearman 0.9999），但本分析只取现版本，避免 1.85 局在 1.88.6 Hydrator 下的 hydration warnings。
- **己方 \(X_{50}\)**：`spikes/dummy-ladder/out-adaptive-all/curves.json` 中 `bbVersion == 1.88.6.0` 的板，**966 板**（interior 814、below 152）。同一批板曾被 race-pool 分析用过（t5–12、814 interior）。
- **对手 \(X_{50}\)**：同 81 局的 `Input.Opponent.Side` 用同一套 v2 自适应流程测（新增 `DummySim --measureSide opponent`：把 7 个木桩放到 Player 侧、保留真实对手板），输出 `spikes/dummy-ladder/out-opp-188/curves.json`。对手侧口径用"同板换侧后与己方口径一致"验证（`verify_side_opp.py`）。
- **有效板**：只用 `status == "interior"`（\(X_{50}\) 有内点、CI 有限）。`below/above` 截断，早期回合大量 `below`，故 **主分析从 t5 起**（fact：t5 以前刻度不稳）；t13–17 只做描述，不进主检验。
- **时间轴**：`gameId` 前缀是 `YYYYMMDD_HHMMSS`，按字符串升序 = 真实时间顺序。顺序号 1..81，同时标出日期刻度。

## 3. 统计

1. **描述**：分回合（t5–t12）两线的原始点 + 10 局 trailing 均线（在 \(\log_2\) 域计算，窗口只在非空板上滑动；与 `tools/progress_view/series.py::rolling_mean` 同语义）。均线在 log 域做，避免大 \(X_{50}\) 回合把均值拉偏。
2. **主检验**：混合固定效应 OLS：\(\log_2 X_{50} \sim \text{seq}_c + \gamma_t + \varepsilon\)（`seq_c` 为对局顺序号中心化，\(\gamma_t\) 为回合固定效应），**按局聚类 bootstrap**（B=2000，整局重采样）给斜率的 95% CI。分别对我、对手、对局强度 \(I\) 跑。报告"每 10 局变化百分比" \(=2^{10\hat\beta}-1\)。
3. **分回合检验**（描述性）：每个回合单独 OLS 斜率 + Spearman ρ，BH-FDR 校正后看有没有单回合异常；同时给 MDE（由 CI 宽度反推），避免把"没检出差"说成"确定没变"。
4. **稳健性**：(a) 前后半段（前 40 局 vs 后 41 局）同回合中位数差；(b) 只取 t6–t12（去掉最不稳的 t5）；(c) 按天聚合的中位数序列（11 个点）；(d) 检查回合组成/存活回合是否随时间变化（避免"活得更久→更晚回合样本变多"造成伪趋势）。
5. **多重比较**：主检验 3 个（我/对手/强度）用 BH-FDR；分回合 8×2 作为探索性，标注 q 值。

## 4. 考虑过的替代方案

- **用分位（0–1）代替 \(X_{50}\)**：分位是相对参照池的，参照池本身随时间扩张；且上一版 progress-trend 用了分位。本次要的是"绝对强度"，用 \(X_{50}\)。分位留作交叉检查（见报告附录，可选）。
- **把对手板 JSON 整体换到 Player 侧再测**：不用改 C#，但会改变测量配置（侧 flags、手牌/英雄技能归属），不如"只在对面放木桩"干净。选后者。
- **10 点均线画在原值域**：大回合会主导，不选；在 \(\log_2\) 域。
- **按月/按周聚合**：窗口只有 11 天、81 局，按天 11 个点已经是极限。

## 5. 验收方式

- `python spikes/x50-trend/build_dataset.py` 产出 CSV，行数 = 81 局 ×（t5–t12 有效板数），且 boardId 唯一、我/对手同板成对。
- `python spikes/x50-trend/analyze.py` 产出 `analysis.json`：主检验系数/CI/q、分回合表、稳健性数字、图 PNG。
- 独立复算：第二份脚本（或第二 agent）从 curves 直接重算主检验斜率，与 `analysis.json` 一致。
- 抽 1 局人工核对：图上某点 = CSV 里该局该回合的值 = curves 原始值。

## 6. 风险与回退

- **对手侧口径错误**：用换侧 ground-truth 校验；若校验不过，退回"对手用己方板的反向估计不可行"并明确报告不可比，不硬出图。
- **样本小**（81 局、每回合 45–81 板）：只能检出不小于约 10–15%/10 局的漂移；报告要写 MDE，不说"强度没变"。
- **选择效应**：对局强度随 MMR/匹配变化不可观测；只描述相关，不做因果。
- **数据/脚本都是 spike**：输出在 gitignore 的 `spikes/**/out*/` 与 `data/progress/`，不并入正式管线；不改主分位。
