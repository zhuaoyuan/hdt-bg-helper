# 方案：当前版本对局战力时序

- **状态：** implemented
- **任务：** 主线外。用现有标准层和分位，看当前模拟池里对局是否随时间变强、活得更久。
- **作者 / 日期：** agent / 2026-10-11
- **相关：** ADR-0015（当前池 `1.85.0.0`）、ADR-0003（分位定义）、`data/strength/<simPool>/strength.jsonl`

## 1. 目标与非目标

**目标：** 一条命令生成离线 HTML。横轴是当前模拟池对局的顺序号（按 `gameId` 时间升序，从 1 起）。三条图：

| 图 | 纵轴 |
| --- | --- |
| 各回合战力 | 该回合己方分位、对手场面分位（0–100） |
| 全局综合战力 | 该局可用回合分位的算术平均（己方、对手各一条） |
| 生存回合 | 该局最后一次战斗的回合号 |

页首给出顺序号与这三项的 Spearman，用来看有没有随时间上升，不把它写成因果结论。

**非目标：** 不重算己方分位、不新跑模拟、不改参照池、不做 P4 覆盖层。对手分位缺缓存时留空，不补模拟。

## 2. 依据

- 己方分位已经在 `data/strength/1.85.0.0/strength.jsonl`（池成员 1.85.0.0 与 1.88.6.0）。
- 对手场面的循环赛次数在 `cache.sqlite`；复盘只给单局写过 `strength_opp.jsonl`。点估计复用同一套 \(S/Q\)，不算 bootstrap 区间。
- 生存回合优先用标准层该局最大 `turn`；标准层没有该局时，用分位文件里出现过的最大回合，并在页上标明来源。

## 3. 方案

`python -m tools.progress_view` 读分位、标准层，可选从缓存补对手点估计，写出 `data/progress/<simPool>.html`（gitignore 的 `data/`）。

综合战力只平均 `percentile` 非空的回合。`insufficient` 不计入分子分母。滚动均值窗口默认 8 局，只在有值的局上滑动。

## 4. 考虑过的替代方案

用 HDT 当场胜率当「对手战力」：那是这一对的胜率，不是对手场面在池里的分位，和己方分位不可比。不选。

对全部对手场面重跑 bootstrap：和现有己方文件重复花约 10 分钟，图上不需要区间。不选。

## 5. 验收方式

`python -m unittest tools.progress_view.test_series` 用合成行检查排序、平均、生存来源。本机再跑 CLI，HTML 能打开，局数与分位文件中的池内局数一致。

## 6. 风险与回退

对手点估计在缓存缺对时为空，曲线会断。删掉 HTML 不影响分位文件。`--compute-opp` 会把新的点估计行追加进 `strength_opp.jsonl`，不覆盖已有分位。

## 7. 任务拆分

单步：工具 + 合成测试 + 本机出图。
