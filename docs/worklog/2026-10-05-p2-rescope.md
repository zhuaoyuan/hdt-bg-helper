## 前提（已有证据）

- 诊断插件 0.1.0 已经是事实上的采集工具：48 局 537/539 场完整 `_input`+`Output`（`facts/diag-capture-batch-20261003.md`），团子版 diag 与官方 schema 一致（`facts/diag-tuanzi-compat-20261004.md`）。
- 团子对战记录每回合给：双方英雄、双方随从（名、金、攻-血）、模拟五率与次数、实际胜负与伤害；局末给名次和分数变化。拔线回合无实际结果；「直接拔线」回合连阵容都没有，diag 也缺该回合 Combat Output（`facts/diag-disconnect-completeness-20261005.md`）。
- 团子记录**不能**替代 diag：没有计数器、饰品、手牌、任务、畸变等完整 Input。

| 原 P2 需要自己做的事 | 团子记录覆盖情况 |
| --- | --- |
| 证明记下的 `Output` 就是 HDT 当场显示的（排除残留 invoker） | 五率+次数逐回合对照即可，已 10/10 |

## 建议的 P2 结构

最大的简化来自「诊断插件已经能用」，团子记录补上了独立校验和实际结果两块，使得不必再自建一套从实体重建 Input、从日志推断战果的管线。

1. **P2-T0 离线重放 + 往返验证**（合并原 T0、T5）：`_input` → BB `Input` → 按 `meta` 的 BB 版本独立进程模拟 → 与记录 `Output` 对照。附带 Q-009/Q-011/Q-013。
2. **P2-T1 短方案 + ADR**：diag 目录格式即原始层；标准层由离线导入脚本生成；`_input` 为主数据源、实体快照仅作后备。不再设计独立的三层存储和 schema 演进体系。
3. **P2-T2 诊断插件转正**（替代原 T2、T3）：只做必要补丁——匿名化加词边界；`records.jsonl` 局末压缩。残留 invoker 过滤、`2022=0` 选取放到离线导入里做，插件不改；`2717` 补录、`hearthstoneBuild` 修正降为可选。
4. **P2-T3 离线导入与质量报告**（替代原 T4、T6、T7）：diag + 团子文本批量配对 → 每回合一行（回合、对手英雄、Input 引用、Output、实际结果、伤害、名次、完整性状态）。完整性规则：单人、有本场 Combat `Output`、非中途启用 = `ready`；清单缺口字段非零或双人 = `partial`；直接拔线 = 缺失。报告即原 T6；这张表也是 P3-T0 的输入和「HDT 当场胜率」基线（原 T7 的分析用途）。

退出标准建议：连续 10 局中，非拔线回合 `ready` ≥ 90%；`ready` 回合团子阵容+五率对照 100% 一致；同版本 BB 重放五率与记录之差在两次抽样合并误差的 3σ 内。

P3-T0 只依赖第 1、4 项，可以更早开工。

## 风险

- **依赖团子**：格式变化或停更时，实际战果退回 diag 相邻回合血量差分、名次退回实体标签。现在不实现，只在方案里留口子。
- **拔线减少实际结果样本**：10-05 当日拔线很多，P3-T0 做「分位与实际战果相关性」时样本会变少。需要所有者决定是否在采集期少拔线。
- 团子文本没有对局 id，批量配对靠日期、英雄 CardId 和阵容多重集；现有 `eval_tuanzi_crosscheck.py` 只支持单局。
