# 2026-09-25 Q-001 / Q-003 / Q-005 调研

## 目标

- Q-001：`BobsBuddy.dll` 的核心类型是否公开，能否自己构造输入并调用模拟。完成标准：有公开签名清单，并有一个能跑通的最小调用。
- Q-003：收集 HDT / Bob's Buddy 的许可与条款原文，整理成事实交所有者判断。
- Q-005：确认插件如何引用 HDT 和闭源 DLL。完成标准：本机实际编译出一个空插件。

## 做了什么

1. 下载官方 `BobsBuddy.zip`（1.78.8），和本机 HDT 自带的 1.76.0 对比。
2. 写 `spikes/bobsbuddy-api/ApiDump`（.NET 8 + `MetadataLoadContext`），导出两个版本的公开签名到 `out/`（不入库）。只读元数据，没有反编译方法体（Q-003 结论出来之前不做更深的分析）。
3. 写 `spikes/bobsbuddy-api/MinimalSim`（net472 x64），照 HDT 的方式构造 3 个白板场面并调用 `SimulateMultiThreaded`，在两个 BB 版本下都跑通。
4. 查许可：HDT README、仓库 `licenses/`、GitHub API、`HearthSim/legal` 的 `TERMS.md`、issue #4063 和 #4509、HDT `PluginManager.cs` 的屏蔽逻辑。
5. 查插件构建：官方 wiki、社区插件 HDT_BGrank 的 csproj、HDT GitHub Releases；写 `spikes/hdt-plugin-skeleton` 并用 .NET SDK 编译成功。

## 发现

- Bob's Buddy 核心类型全部公开，不需要反射就能在独立进程中调用。白板 7 对 7 在 6 线程下约 150 ms 完成 1 万次模拟。
- 1.76.0 到 1.78.8 核心 API 只有 `Player.MagnetizeCounter`（`int?` 变成 `int`）一处变化，但删除了 Aberration 种族等 20 多个卡牌实现。说明新版 DLL 可能模拟不了旧补丁的场面，登记为 Q-011。
- `Player.DeepBluesCounter`、`AnySpellCounter`、`BackToBackCounter` 是公开属性，HDT 源码从不赋值。已记入数据清单"待补全"。
- 离线模拟需要自己加载 CardDefs：HDT 运行时会下载最新的 CardDefs 替换 HearthDb 自带数据（`CardDefsManager.cs`）。
- HDT 和 Bob's Buddy 都是 All Rights Reserved 的专有软件。条款只授予个人非商业使用，禁止修改、衍生、再分发，没有提到插件。官方对"会玩酒馆战棋的 agent"明确不支持；Blizzard 要求后，HDT 在代码里屏蔽了 Reconnector 类插件。
- 插件只需要 .NET SDK 就能构建。HDT 从 `%APPDATA%\HearthstoneDeckTracker\Plugins` 同步插件到安装目录，再用 `Assembly.LoadFrom` 加载到同一进程。
- HDT 的 GitHub Releases 停在 v1.55.6，CI 拿不到新版二进制文件。
- 环境：`dotnet` 不在 PATH 上，没有 `gh`；已写入 `AGENTS.md`。
- 所有者已配置 git 身份并完成初始提交 `d28b7f8`。
