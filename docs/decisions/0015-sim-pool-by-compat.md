# ADR-0015：战力参照池按模拟池分组，不按 BB 文件版本各成一桶

- **状态：** accepted（所有者 2026-10-11 派发 `docs/process/prompts/sim-pool-versions.md` 时确认方向：1.85.0.0 与 1.88.6.0 并入同一模拟池；其它未通过同输入兼容测试的实际版本单独成池）
- **日期：** 2026-10-11
- **相关：** 取代 ADR-0011 的「分桶键 = BB 版本 + 回合」；不取代留一局循环赛、确定性面板、L0/L1、`insufficient`。L2 仍关闭。`design/P3-sim-pool.md`、`facts/replay-roundtrip.md` §3、`facts/sim-pool-members.md`

## 背景

ADR-0011 把参照池按 Bob's Buddy **文件版本**切开，避免跨 DLL 重放把五率算偏。Q-011 已核实：1.78.1→1.85.0 有显著偏差（40 场里 3 场）；1.85.0→1.88.6 同输入 100/100 场在 3σ 内（`facts/replay-roundtrip.md` §3.1–§3.2）。§3.3 因此写过「不把两版本场面混进同一战力参照池」。文件版本继续分桶会让 1.88.6 桶长期偏窄，而同输入测试已经说明这两份 DLL 可以共用一份对战次数。

## 决定

1. **分组键改为模拟池 `simPool` + 回合。** `simPool` 等于池内最早的 `bbVersion`。实际版本 `bbVersion` 仍是采集时的 `meta.bobsBuddy.fileVersion`，单场 Input 选 DLL 重放时仍用它。
2. **并池条件是同输入五率兼容**（与 `facts/replay-roundtrip.md` §3 相同：五率 3σ 一致，且没有 1.78→1.85 那种显著偏差场）。E5 / 旧 L2 的 \(|\Delta Q|\) **不是**并池条件。旧 L2 保持关闭。
3. **初始成员：** `1.85.0.0` 与 `1.88.6.0` 同池，`simPool = 1.85.0.0`（证据 §3.2，不为此重跑 100 场）。`1.78.1.0`、`1.80.1.0`、`1.81.2.0` 未与 1.85 通过测试，各自单独成池。版本表在 `tools/strength/sim_pools.json`。之后新版本只有 `pool-check` 通过且结论写入 `docs/facts/` 后，才能 `pool-join`。
4. **对战次数按池共享。** `pairKey = sha256(simPool | assemblerVersion | 规范化 Input)`。同一拼装输入在池内只留一份次数；1.85 与 1.88.6 已有次数按 hash 相加，不为换 DLL 重跑。池内新的缺对用该池已安装成员里最新的 DLL 模拟。
5. 留一局循环赛、面板上限 K、L0/L1、`G_min`、`insufficient` 仍按 ADR-0011 的其余条款。

## 考虑过的方案

| 方案 | 优点 | 缺点 | 为什么没选 / 为什么选 |
| --- | --- | --- | --- |
| 继续按文件版本分桶 | 与 ADR-0011 原文一致 | 1.88.6 样本长期偏少；已通过的同输入测试用不上 | 没选 |
| 用 E5 的分位差决定并池 | 直接看战力数字 | 那是另一套问题；同输入五率才是「能不能共用 DLL」 | 没选 |
| **同输入五率通过才并池，池 Id 取最早实际版本** | 兼容的版本共享对战；不兼容的仍隔离 | 混池后的分位不必等于单版本分位 | **选中** |

## 后果

- 正面：1.85 与 1.88.6 的场面互为同伴和对手；缓存不按 DLL 文件版本拆开。
- 代价：分位与「只用 1.88.6」不完全相同，以 `data/strength/<simPool>/strength.jsonl` 为准。旧的按文件版本分位文件保留、停用。
- 跟进：升级流程改为先 `pool-check` 再决定并池或新池（`docs/process/prompts/version-upgrade.md`）。

## 推翻条件

- 某次 `pool-check` 在已并池的两份 DLL 上出现 §3.1 那种显著偏差场；或
- 池内跨版本对战用「最新已安装 DLL」补算后，与当时采集 DLL 的同输入五率不再满足 §3 的通过条件。
