# ADR-0001：采用分类文档体系支撑 agent 驱动开发

- **状态：** accepted（所有者 2026-09-25 在对话中授权 agent 负责项目初始化）
- **日期：** 2026-09-25
- **相关：** P0-T1

## 背景

本项目主要由 AI agent 在多个互相独立的会话里推进。每个会话开始时 agent 没有之前的记忆，只能靠仓库里的内容接上。常见的失败方式有：

- 结论只留在对话里，下次会话重新调研；
- 把推断当成事实，错误一路传下去；
- 决定被悄悄推翻，没人知道当初为什么这么选；
- 不知道"现在做到哪了"。

## 决定

1. 根目录 `AGENTS.md` 作为唯一入口，规定会话开始必读和结束必做。
2. 知识按性质分目录存放：状态、路线、背景、事实、决定、架构、方案、调研、过程、日志（见 `docs/README.md`）。
3. `docs/status.md` 是"现在在哪"的唯一事实源，每次会话结束都要更新。
4. 事实必须带来源和基线版本；推断单独标注并登记为未决问题。
5. 决定用 ADR 记录，只增不改。
6. SDLC 的每个环节配一份提示词（`docs/process/prompts/`），让不同会话的 agent 用一致的方式工作。

## 考虑过的方案

| 方案 | 为什么没选 / 为什么选 |
| --- | --- |
| 只写一个大 README | 事实、决定、过程混在一起，很快就没人能维护 |
| 用外部工具（Issue 系统、Wiki）管理 | 离开仓库后 agent 不一定能读到；版本不跟着代码走 |
| **仓库内分类文档 + 固定入口** | 选中：agent 天然能读写，跟代码一起版本化 |

## 后果

- 正面：任何会话都能从 `AGENTS.md` → `status.md` 快速接上；事实可追溯。
- 代价：每次会话要花少量时间维护文档。
- 跟进：如果某类文档长期没人更新，在流程复盘时考虑合并或删除。

## 推翻条件

文档维护成本明显超过它带来的价值（例如同一信息需要在三处以上同步）。
