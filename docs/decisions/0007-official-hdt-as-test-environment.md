# ADR-0007：以本机官方版 HDT（保持最新）作为实测与验证环境

- **状态：** accepted（所有者 2026-09-25 对话确认：已安装官方版，今后持续更新到最新版本）
- **日期：** 2026-09-25
- **相关：** 取代 ADR-0005；关闭 Q-010、Q-012；Q-002、Q-011、P2-T5，`facts/local-environment.md`

## 背景

- ADR-0005 选择了本机的第三方"团子版"HDT 作为实测环境。之后发现它带拔线功能（有账号风险），对战记录里有 372 场战斗因拔线没有结果，且无法完全排除它改过模拟输入逻辑（`facts/hdt-log-simulation-input.md` 第 5 节）。
- 2026-09-25 所有者安装了官方 HDT：`%LOCALAPPDATA%\HearthstoneDeckTracker\app-1.58.3`，文件版本 1.58.3.8362，自带 BobsBuddy.dll 1.78.1.0（`facts/local-environment.md`）。官方版使用 Squirrel 自动更新。
- 官方版和团子版共用数据目录 `%APPDATA%\HearthstoneDeckTracker`（日志、`Plugins/`、`BgsLastGames.xml`）。
- 已有的 26 个历史日志全部来自团子版（1.49.2 – 1.57.12），而且只有团子版会在每个随从后打印 CardId（`facts/hdt-log-simulation-input.md` 第 4.4 节）。

## 决定

- 实测和验证以本机官方 HDT 为准，所有者会让它保持最新版本。插件只面向官方版开发和验证。
- 源码分析仍以 `AGENTS.md` 里写明的上游基线为准。发现安装版本比基线新时，按 `docs/process/prompts/version-upgrade.md` 升级基线。
- 凡是依赖运行时行为的结论（反射访问内部字段、日志格式、战斗中更新时机），都要写明 HDT 和 BobsBuddy.dll 的版本。插件采集的每份快照也要记录这两个版本（Q-011）。
- 团子版的历史日志继续作为**近似重建场面**的数据来源（Q-009、Q-011、Q-013 原型）。用到它们的结论要注明"来自团子版日志"；在需要和 HDT 模拟结果做精确对照的场合（P2-T5），只用官方版产生的数据。
- 不再调查团子版的改动范围（Q-010 关闭）。

## 考虑过的方案

| 方案 | 优点 | 缺点 | 为什么没选 / 为什么选 |
| --- | --- | --- | --- |
| 继续用团子版（ADR-0005） | 所有者无需改变习惯 | 拔线功能有账号风险；改动范围说不清；拔线战斗会污染结果数据 | 所有者已换用官方版 |
| 官方版固定在基线版本不更新 | 运行时和源码基线始终一致 | 游戏更新后旧版 HDT 和 BB 会失效，而且所有者日常要用最新版 | 不现实 |
| **官方版，保持最新** | 和上游源码一致；数据干净；就是所有者的日常环境 | 版本会变，源码基线需要跟着升级；每次 HDT 更新都可能影响插件 | 选中 |

## 后果

- 正面：运行时结论可以直接对应上游源码；不再有拔线导致的缺失结果；插件的目标环境和将来可能的其他用户一致。
- 代价：HDT 和 BB 会随时更新，插件要能容忍版本变化，采集数据要带版本号；源码基线升级会更频繁。
- 代价：官方版日志没有 CardId 行，同属性相邻随从还可能被折叠，历史日志的这两个优势不能再补。现有的团子版日志需要备份保存。
- 需要跟进：
  - 官方版产生带模拟的日志后，复核日志格式与 `facts/hdt-log-simulation-input.md` 一致，并更新 Q-004 结论的适用范围。
  - 团子版程序目录 `C:\Program Files\HDT` 仍在磁盘上；如果所有者同时启动两个版本，它们会读取同一个插件目录。

## 推翻条件

- 官方 HDT 停止维护，或者变更使插件无法加载；
- 所有者改用其他追踪器。
