# ADR-0008：个人采集以团子版 HDT + 对战记录对照为主

- **状态：** accepted（所有者 2026-10-04 对话确认：后续用团子版采集更多数据，并用团子自带对战记录做对照）
- **日期：** 2026-10-04
- **相关：** 部分修订 ADR-0007 的「采集环境」条款；不推翻「插件接口以官方 HDT 行为为准」；`facts/diag-tuanzi-compat-20261004.md`、`process/field-capture.md`

## 背景

- ADR-0007 因拔线风险与改动范围不明，把实测环境定为官方 HDT。
- 2026-10-04 在团子版 HDT 1.58.6.0 上跑诊断插件 0.1.0，一局 diag 与官方同 BB 版本 schema 兼容；与团子对战记录文本的阵容、BB 五率 10/10 对齐（`facts/diag-tuanzi-compat-20261004.md`）。
- 团子版每日对战记录（英雄、随从攻血金、模拟五率、实际结果）是现成的交叉验证源，官方版没有同等文本。

## 决定

1. **个人数据采集**优先在团子版 HDT 上进行，同时启用 `HdtDiagLogger`；每局 diag 目录与当日对战记录文本配对保存（仓库侧：`data/BgHelperDiag/` + `data/tuanzi/`，均不入库原始大文件时可 gitignore）。
2. **正确性对照**以团子对战记录为准核对：双方阵容（攻/血/金）、模拟五率与次数；实际战果用文本 + 己方血量差分，**不要**把 `medianDamage ≠ 实际伤害` 单独判为解析错误（低置信 RNG 预期内）。
3. **插件开发与字段语义**仍以官方 HDT / 上游源码 + 官方 diag 样本为权威；团子版若出现与官方不一致的 Input/Output 字段，记 facts 并按官方语义处理。
4. **继续避免拔线**：需要完整「实际结果」做对照的对局不要拔线；拔线场次可保留 diag，但交叉验证标为无实际结果。
5. ADR-0007 中「P2-T5 精确对照只用官方数据」改为：diag `_input`/`Output` 的 schema 与重放以 `meta` 版本为准，官方与团子 diag **可混用**；团子**历史 Power 日志**仍只作近似重建，不作精确对照。

## 考虑过的方案

| 方案 | 优点 | 缺点 | 为什么没选 / 为什么选 |
| --- | --- | --- | --- |
| 继续只采官方版（ADR-0007 原文） | 与上游完全一致 | 缺少对战记录文本，交叉验证成本高 | 所有者选择恢复团子采集习惯 |
| 只采团子、不用插件 | 有对战记录 | 没有完整 BB Input，无法支撑重放/分位引擎 | 不满足项目目标 |
| **团子采集 + 插件 + 对战记录对照** | 有完整 diag，又有廉价对照 | 拔线风险；团子可能再改私货 | 选中；用对照与 meta 版本兜底 |

## 后果

- 正面：可持续用对战记录抽检解析正确性；采集量不依赖换客户端习惯。
- 代价：agent 分析时要跑 `eval_tuanzi_crosscheck.py`（或后续批处理）；文档与 `field-capture.md` 需同时覆盖团子路径。
- 需要跟进：批量对照脚本（多局配对）；若团子 BB 默认迭代次数长期为 19998，重放对照勿写死 9996。

## 推翻条件

- 团子版改动使 diag Input/Output 与官方分叉且无法机械对齐；
- 所有者改回只使用官方 HDT 采集。
