# ADR-0004：插件采集保持轻量，原始数据只追加，计算异步化

- **状态：** proposed（P2-T1 设计方案时细化后请所有者确认）
- **日期：** 2026-09-25
- **相关：** P2、P4、`context/early_discussion.md`（A3 第二节）

## 背景

- HDT 的事件处理和 `OnUpdate()`（约 100ms 一次）都跑在 HDT 自己的流程里，插件在这里做重活会拖慢 HDT 甚至游戏体验。
- Bob's Buddy 单场模拟就要 1.5–5 秒、占用一半 CPU 核心（`facts/bobsbuddy-simulator-input.md`），战力分位需要对很多参照场面做模拟，计算量远大于此。
- 字段含义可能随游戏版本变化，今天认为无用的标签以后可能需要。

## 决定（提议）

1. **采集与计算分离。** 插件在游戏事件里只做读取、标记阶段、写入本地；模拟和分位计算放到后台线程或独立进程。
2. **三层数据。** 原始层（实体、标签、事件，按时间顺序只追加，带 schema 版本）→ 标准层（对局、玩家、回合快照、随从、结果）→ 模拟层（规范化的模拟器输入、模拟器版本、结果）。标准层和模拟层都能从原始层重新生成。
3. **本地存储**，不上传。玩家标识在本地匿名化。
4. 插件生命周期可关闭、可卸载，并记录自身版本。

具体存储格式（如 JSONL + SQLite）在 P2-T1 设计方案中确定。

## 考虑过的方案

| 方案 | 为什么没选 / 为什么选 |
| --- | --- |
| 只存 CSV | 丢失标签、未知字段和事件顺序，无法重新解析 |
| 插件内直接算分 | 阻塞 HDT；难以复算 |
| **原始层只追加 + 投影 + 异步计算** | 选中：可重放、可复算、不影响 HDT |

## 后果

- 正面：采集逻辑简单、稳定；以后可以对历史数据重新解析和重算。
- 代价：原始数据体积较大；要维护投影逻辑和 schema 版本。
- 跟进：P4 实时显示需要评估延迟预算，可能需要预计算或缓存参照池结果。

## 推翻条件

实测显示原始层体积或写入开销不可接受。
