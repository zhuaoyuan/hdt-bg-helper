# ADR-0012：阵容图以无状态单侧渲染为单元，允许本机 HDT 贴图

- **状态：** accepted（所有者 2026-10-05 对话确认）
- **日期：** 2026-10-05
- **相关：** P3-T6、`design/P3-board-render.md`、`facts/hdt-past-opponent-board-render.md`、ADR-0006

## 背景

P3-T6 要离线画出诊断记录里的场面图。方案初稿默认「一张图画双方 + 自绘边框角标 + 标题含英雄/五率/战果」。所有者确认：

1. 需要支持己方、对手、双方并排、跨局对战等多种组合，不只是「本场对手」；
2. 本机可读 HDT 的 `Resources/Minion` 贴图作皮肤（不入库），与 ADR-0006 的个人非商业本地使用相容；
3. 第一版视觉范围收窄到随从横排即可，英雄头像、五率、战果等可由上层用同一数据另行拼接。

## 决定

1. **核心 API 是无状态的单侧渲染单元**：输入一侧的 `MinionView` 列表（及皮肤/素材句柄），输出一张只含该侧随从的 PNG（或可合成的位图）。不依赖「本场己方/对手」「是否同一局」等上下文。
2. **组合由调用方完成**：CLI / 复盘视图需要双方或跨局对战时，调用两次单侧渲染再拼接；拼接布局不属于 v1 核心库的必交付。
3. **边框与关键词角标优先用本机 HDT 贴图**（从已安装 HDT 的资源或用户指定目录只读加载；**不复制进仓库、不分发**）。找不到时回退到自绘。
4. **v1 只画随从**（肖像、攻血、金色、关键词角标）。英雄、五率、战果、饰品、英雄技能、奥秘不进 v1 图面；需要时后续解耦实现。

## 考虑过的方案

| 方案 | 优点 | 缺点 | 为什么没选 / 为什么选 |
| --- | --- | --- | --- |
| 一张图固定双方 + 标题元数据 | 一条命令出完整复盘卡 | 难复用到跨局/单侧；元数据与画面耦合 | 未选 |
| 只画对手（仿 HDT 悬停） | 与 HDT 一致 | 不能画己方或跨局 | 未选 |
| 无状态单侧单元 + 可选拼接 | 组合灵活；测试面小 | CLI 要多一步才能出「双方图」 | **选中** |
| 永远自绘边框角标 | 无 HDT 依赖 | 观感差 | 作回退 |
| 本机读 HDT 贴图（不入库） | 观感接近 HDT；符合个人使用 | 依赖本机安装路径；升级可能改资源名 | **选中**（找不到则自绘） |

## 后果

- 正面：同一渲染器覆盖己方/对手/双方/跨局；皮肤与数据解耦；v1 范围清晰。
- 负面 / 代价：默认 CLI 若只出单侧，双方复盘图需调用方拼接；HDT 资源路径要探测或可配置。
- 需要跟进：实现时写清 HDT 贴图查找顺序与回退；验收以单侧图为主。

## 推翻条件

- 单侧单元无法满足复盘产品的布局需求，且拼接成本明显高于「固定双方画布」；
- 本机读取 HDT 贴图在常见安装布局下长期失败，或与许可理解冲突（需所有者重新评估 ADR-0006 边界）。
