# ADR-0013：赛后复盘原型以离线静态 HTML 交付

- **状态：** accepted（所有者 2026-10-05 对话确认：离线静态 HTML；v1 不做方向标注；实现不与 P3-T3 并行）
- **日期：** 2026-10-05
- **相关：** P3-T5、`design/P3-T5-review-view.md`、ADR-0003、ADR-0004、ADR-0012

## 背景

P3-T5 要交付「按回合展示分位、置信度、实际对手和结果」的复盘视图原型。上游已有：标准层 `turns.jsonl`（P2-T3）、计划中的 `strength.jsonl`（P3-T3）、单侧阵容图（P3-T6 / ADR-0012）。架构总览把复盘视图放在离线侧，与 P4 局内覆盖层分开。愿景要求赛后重分析、不确定就明说；个人本机使用，不托管、不上传（ADR-0006 边界）。

需要决定原型的**交付形态**，避免实现时在 Streamlit / HDT 窗口 / 笔记本之间摇摆，并影响 P4 边界。

## 决定

1. **P3-T5 主交付是离线生成的静态 HTML 单局页**（可附 `model.json` 与阵容 PNG 相对路径），由 `tools/review_view` CLI 从本机 JSONL + 已有图拼装。
2. **不引入常驻 Web 应用框架**（Streamlit / Gradio 等）作为原型必选项；不在 HDT 进程内做赛后窗口（留给 P4 另议）。
3. **打开方式以本机文件为准**（资源管理器 / `file://`）；可选的本机 `http.server` 仅作便利，不是契约。
4. 视图**只消费**标准层与 strength 输出，不在视图里重算分位或调用模拟器。

## 考虑过的方案

| 方案 | 优点 | 缺点 | 为什么没选 / 为什么选 |
| --- | --- | --- | --- |
| 离线静态 HTML + CLI | 零额外运行时；单局可归档；与现有 tools 一致 | 交互弱于应用 | **选中** |
| Streamlit / Gradio | 交互开发快 | 依赖与常驻进程；难固定「某一局快照」 | 未选 |
| Jupyter 报告 | 分析灵活 | 不是打开即用的复盘产品 | 分析可另用，不作 T5 交付 |
| HDT 内嵌 WPF | 靠近游戏 | 插件面大；与 P4 混淆 | 未选 |
| 纯 Markdown 表 | 极简 | 缺时间线与阵容点选 | 仅可作调试旁路 |

## 后果

- 正面：交付边界清晰；可与 P3-T3 并行用 mock 做 UI；输出进 `data/` 不入库即可。
- 负面 / 代价：复杂交互（可编辑标注、多局筛选）以后要另做或升级形态。
- 需要跟进：方案获批后实现 `tools/review_view`；若所有者强依赖可编辑标注，再开 T5.x / P5，不默默塞进本 ADR。

## 推翻条件

- 静态页在本机浏览器下无法稳定展示相对路径资源，且轻量 `--serve` 仍不可接受；
- 所有者确认赛后复盘必须进 HDT 窗口，且愿意把该工作前移并重划与 P4 的边界；
- 静态 HTML 无法满足验收中的时间线 / 点选 / 缺数文案，而换形态成本更低。
